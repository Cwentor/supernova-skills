# write-research · 面向一手来源的查证式调研

一句话：用户要「查清楚 X」时，只认一手来源做查证，产出一份逐条标注出处的单一 Markdown 文件，放进仓库符合惯例的位置。

## 三条核心纪律

### 纪律一：只认一手来源，每条论断回溯到所有权方

- 一手来源 = 论断的「所有权方」自己发布的材料：官方文档、源代码、规范/标准原文（spec）、第一方 API（官方接口文档，或对官方接口的实测）。
- 二手来源 = 对一手材料的转述：博客、教程、新闻稿、第三方总结、论坛回答、AI 概述。二手会过时、抄错、夹带私货。
- 判定口诀：问「这条论断归谁所有」。参数默认值归源码所有；某行为是否受支持归官方文档/源码所有；协议语义归规范原文所有；接口实际返回什么归第一方 API 实测所有。
- 二手材料的唯一合法用法是当线索：教程说「X 支持 Y」→ 顺着它去官方文档/源码确认；确认后引用一手，确认不了就不写。
- 每条事实性论断都要能指回拥有它的一手来源。查不到一手出处的论断，要么删掉，要么显式标注「未在一手来源确认」，绝不无声保留。

### 纪律二：产出单一 Markdown 文件，逐条标注来源

- 一次调研 = 一个 `.md` 文件：不散落多文件，也不只留在对话里。
- 文件骨架：标题 → 调研问题与范围 → 发现（每条论断带出处）→ 来源清单。
- 推荐脚注式引用格式：

  ```markdown
  ## 发现
  论断 A 的表述 [^1]；论断 B 的表述 [^2]。

  [^1]: <来源标题> · <官方文档/规范名> — <URL>（访问日期 YYYY-MM-DD）
  [^2]: <仓库路径>#L<行号>，或 <命令> 及其实测输出
  ```

- 出处写法：网页一手写「标题 + URL + 访问日期」；源码一手写「路径 + 行号或符号名」；实测一手写「可复现命令 + 观察到的输出」。

### 纪律三：存放位置遵循仓库惯例

- 落盘前先看仓库现状：有没有 `docs/`、`notes/`、`research/` 之类既有目录？同类文件怎么命名（kebab-case、日期前缀……）？
- 有惯例 → 照惯例放、照惯例命名。
- 无惯例 → 放合理位置（如 `docs/research/`），并在回复里告诉用户放在哪、为什么。位置永不静默。

## 执行方式：先探测能力，再决定怎么跑

- 先写好调研任务书（见下），再选路径：
  - 有后台代理/子代理工具 → 把任务书委托给后台跑，主会话继续干别的活；后台交回后按「红线自查」验收产出。
  - 没有 → 本会话顺序执行同一份任务书。
- 两条路径的产出纪律完全一致，变的只是在哪里跑。

## 调研任务书怎么写

| 字段 | 写什么 | 示例 |
|---|---|---|
| 问题 | 一句话，能判定答没答上 | 「工具 X 的 `--foo` 默认值是什么？」 |
| 范围 | 写明范围外（out of scope）项 | 只查官方文档与源码；不看教程转述 |
| 线索 | 用户给的资料/链接 | 教程 URL（二手，仅作线索） |
| 产出 | 单文件 + 逐条标注 + 存放位置 | `docs/research/x-foo-default.md` |

## 步骤表

| # | 步骤 | 要点 | 完成标志 |
|---|---|---|---|
| 1 | 澄清问题，写任务书 | 问题一句话；范围写明 out of scope | 四字段齐全 |
| 2 | 列一手来源清单 | 每个子问题问「归谁所有」 | 每个子问题有归属 |
| 3 | 选执行路径 | 有后台代理则委托，没有则本会话跑 | 查证开始 |
| 4 | 逐条查证 | 论断回溯一手；二手只当线索；查不到 → 删或标注 | 无悬空论断 |
| 5 | 写单文件 | 按纪律二的骨架与引用格式 | 文件成型 |
| 6 | 落盘 | 按纪律三定位 | 位置确定，必要时已告知 |
| 7 | 红线自查 | 过一遍自查清单 | 全部通过 |

## 最佳示例

用户：「教程里说工具 X 的 `--foo` 默认开启，帮我查证一下。」

任务书：问题 =「X 的 `--foo` 默认值是什么」；范围 = X 官方文档 + 源码；线索 = 该教程 URL（二手）；产出 = 单文件、逐条标注。

产出片段：

```markdown
## `--foo` 的默认值

默认关闭 [^1][^2]。教程所称「默认开启」与一手来源不符，以官方文档为准。

[^1]: X 官方文档 · CLI options — https://x.example/docs/cli#foo（2025-06-01）
[^2]: X 源码 defaults.ts:12 — `foo: false`
```

若官方文档与源码都查不到该参数：写「未在一手来源确认 `--foo` 的默认值」，绝不抄教程充数。

## 常见错误

1. 二手来源冒充一手：直接拿博客/教程/论坛回答支撑论断。教程是抄官方文档的，可能过时或抄错。→ 二手只当线索，论断必须回溯所有权方。
2. 论断无出处：文件里出现没有任何标注的「事实」。→ 每条事实性论断跟出处；查不到一手就删，或标注「未在一手来源确认」。
3. 调研范围漂移：任务书写「查 A」，查着查着一半篇幅在讲 B。→ 范围外的发现只记进文末「范围外线索」一节，不展开；要扩范围，先改任务书并告知用户。
4. 位置静默：文件丢在不合惯例的角落，或不告诉用户放哪了。→ 落盘前先找惯例；无惯例放合理处并明说。

## 红线自查（交付前必过）

- [ ] 每条事实性论断都能指出一条一手出处（官方文档/源码/规范/第一方 API）？
- [ ] 没有任何论断仅由二手来源（博客/教程/论坛/新闻/AI 概述）支撑？
- [ ] 查不到一手出处的论断已删除，或已显式标注「未在一手来源确认」？
- [ ] 产出是单一 Markdown 文件，逐条标注齐全？
- [ ] 存放位置符合仓库既有惯例；无惯例时已告知用户位置与理由？
