# write-beats · 节拍成文

写作**成文（exploit）阶段**的技能：探索已结束，堆已固定。任务不是把堆倒进文章，而是选定一条穿过堆的路，把原料开采出来，走成一篇「节拍（beats）旅程」。

## 定位与分工

- **攒料（explore）**归 write-fragments：搜集、探索、堆原始材料。堆还没攒齐时先去攒料，别用本件。
- **成文（exploit）**是一对姊妹件：本件管**节拍旅程**——文章按什么顺序走、在哪些停顿处拐弯、在哪里收束；write-shape 管**逐段论证塑形 + 形式选择**——一段话如何立论与推进、整篇选什么外壳。
- 拿不准用哪件，走 meta-skill-router。

## 开工两件事

1. 认定堆已固定：用户已给出（或将给出）一份 markdown 原材料文件；开工后不再回头探索、不再往堆里加料。
2. 用户没说文章存哪？问一次，记住路径；此后每个节拍都写进这个文件。

## 方法：分支选择式的节拍旅程

像自选冒险小说（choose-your-own-adventure）那样推进：每个岔路口摆出选项、摆明各自通向什么，用户挑一条，走一步。

1. **确立 prerequisites（先修概念）。** 动笔前与用户敲定：读者入场时已经带有哪些概念——它们从第一拍起就算已 ground。其余概念必须先被某个节拍引入（ground），后续节拍才能依赖。
2. **给 2–3 个候选起始节拍。** 各自是从原材料通向文章的不同入口；每个只能依赖已 ground 的概念，并标注各自会 ground 哪些新概念。先给用户过目；用户选定后，顺带预告这个选择解锁哪些后续路径——让用户望得见前路的一小段。
3. **只写选中的那一个节拍**，写进文章文件，然后停。
4. **重读盘上的文章文件**，再给 2–3 个候选下一节拍：从文章当前站立处可拐向的不同方向；每个都必须从当前 grounded 集可达，并标注各自会 ground 什么。
5. 循环 3–4，直到旅程自然结束。

## Grounding 纪律（本件的心脏）

**概念必须先 ground，才能被依赖。** 读者要么入场就带着它，要么在更早的节拍里见过它。依赖未 ground 概念的节拍会当场丢掉读者——这是旅程唯一走不出的那步棋。

- **两种 ground 途径**：prerequisite（第一拍之前就成立，读者自带，开工时固定）；introduced（某个节拍把它立起来，此后对所有后续节拍有效）。
- **单位是概念，不是词。** 全文一个术语都没有，某个节拍也可能依赖了读者没有的想法。概念有名字（术语）时，ground 意味着想法与术语一起落地。
- **每个节拍干两件事**：依赖已 ground 的概念，同时引入新概念。
- **维护 running grounded 清单**（目前已 ground 的概念集合），每个节拍落地后更新一次。
- **可达性决定分支**：候选节拍可达，当且仅当它依赖的一切都已 ground；选中一个 ground 了概念 X 的节拍，就解锁了所有在等 X 的节拍。给候选时标注各自 ground 什么，用户才看得见各条路通向哪里。
- **prerequisite 设多少，是与用户明着谈的大杠杆**：要得太多，没带这些概念的读者被挡在门外；文内 ground 太多，开头几拍淹死在定义里。开工确立 prerequisites 时敲定这个平衡；之后若某个诱人节拍依赖了还没人 ground 过的概念，回头再谈——修法只有两个：在它前面加一个 ground 该概念的节拍，或把该概念提升为 prerequisite。

## 节拍的尺寸

一个节拍是旅程里的一个动作，只做一件事：设场景、落论点、抛问题、插题外话、转角度。做完就停，把读者留在一个下一拍可以拐弯的地方。尺寸按需：

- 动作就那么大：一句话（「然后接下来的三周，什么都没发生。」）。
- 需要铺垫：一个短段。
- 自成一体的插叙、论证或例子：数段。

一个「节拍」要五段话加三个子标题？那不是节拍，是两个节拍粘在一起。拆。

## 堆是采石场

每个节拍的料都从原材料里开采：意译、拆分、重组、引用，皆可。

## 结束旅程

文章结束 = 旅程完成，**不是堆清空**。大多数堆都会剩下没用上的碎片——这很正常；备料多于所需，本来就是攒料的意义。

## 节奏纪律

- **一次只写一个节拍，绝不提前写。**
- **每次落笔前重读盘上的文章文件**；用户的编辑绝对保留。
- 用户大改了前一个节拍？让它改变后续走向，别当什么都没发生。
- 用户说「重写那一拍」「回到第 3 步换一条」？照做：原地改，其余不动。

## 借口 vs 现实

| 借口 | 现实 |
|---|---|
| 「先把全文写完再给用户看，省得来回打扰。」 | 本件的产品就是节拍旅程本身；一口气写完等于把用户开除出旅程，分支选择的价值全部作废。 |
| 「这个概念大家都懂，不用 ground。」 | 「大家」不存在。没敲进 prerequisites、没被节拍引入的概念就是没 ground；依赖它就丢读者。 |
| 「这两拍关系太紧，写在一起更连贯。」 | 那是两个节拍粘连。连贯来自 grounding 与顺序，不来自把动作糊成一大坨。 |
| 「用户还没选，我先把后面的节拍写了吧。」 | 绝不提前写。候选节拍的可达性由当前 grounded 集决定；提前写是在没有地图的地方画路。 |
| 「堆里还有这么多好料，文章得加长把它们用完。」 | 结束 = 旅程完成，不是堆清空；剩料是常态，不是债务。 |
| 「用户改了前一拍，但我后面的思路已经定了，照旧。」 | 用户的改动是新的地形。重读文件，让改动改变后续走向。 |
| 「prerequisites 按我的默认来就行，不用问。」 | 前提设多少，决定读者被挡在门外还是淹死在定义里；这个平衡必须与用户明着谈。 |

## 红线自查（每个节拍落笔前过一遍）

- 此节拍依赖的每个概念，都在 grounded 清单里（prerequisite 或更早节拍引入）？
- 此节拍新引入的概念，已记入 grounded 清单？
- 刚给出的候选节拍全部从当前 grounded 集可达，且各自标注了会 ground 什么？
- 落笔前重读了盘上的文件？用户此前的编辑一字未动？
- 本次只写了选中的那一个节拍，零提前量？
