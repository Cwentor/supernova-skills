# write-shape：逐段塑形成文

写作分两段：explore（攒料）与 exploit（成文）。本技能属于 exploit：探索已经结束，原料堆已经固定，任务是承诺一个结构，然后从堆里采料把它填成一篇完整的文章。产物是一份独立的文章文件；原料堆文件对本技能只读。

## 体系分工

- `write-fragments`：攒料（explore 阶段），负责挖碎片、攒堆——它的产物就是本技能的输入。
- `write-beats`：与本件同为成文（exploit）阶段的姊妹件，管叙事节拍旅程（故事弧线与读者情绪的推进）。
- 本件：成文阶段的另一半，管逐段论证塑形 + 块级形式选择 + 语气。节拍已由 beats 定好、或文章靠论证而非故事推进时，用本件。
- 前期调研见 `write-research`、`write-market-research`；选题、结构模板、平台文案不归本件（另见 `write-content-engine`）。
- 拿不准该用哪个技能：`meta-skill-router`。

## 输入与前提

- 输入是一份原料堆文件：可以是整洁的碎片清单，也可以是一整面未整理的散文墙或访谈转录。格式无所谓，内容才算数。
- 动手前通读全堆，对堆里有什么形成整体感觉；这一步没做完，不开工。
- 用户没说文章存到哪：问一次，记住路径。
- 探索已结束：不挖新碎片；缺料按「缺料点名」处理。

## 塑形循环

1. **读全堆。** 通读输入文件，形成整体感觉。
2. **确立前置概念（prerequisites）。** 与用户敲定读者进门时自带哪些概念：它们从第一个词起就已落地。其余一切概念必须先被某个块落地，之后的块才能倚靠。
3. **给 2–3 个候选开头。** 每个开头隐含一个不同的论点（thesis）或切入角。全部摆出来，让用户选一个、或拼一个混搭。选定的开头定义文章其余部分必须做到什么。
4. **逐块生长。** 每一步都问：「给定这个开头，读者接下来需要听什么？」从堆里采料回答。下一个块只能倚靠已落地的概念，并在自己落地的同时落地新概念。下一块的形式要明着论证（见「形式论证」），每个选择有据可辩。
5. **边定边追加。** 每谈定一块就立刻写进文章文件，不攒批——让用户看着文章逐块成形。
6. 循环第 4 步直到用户说算完。什么时候算完，由用户决定。

## 概念落地（grounding）

- 每个概念必须先落地，块才能倚靠：读者要么进门就懂，要么在前面的块里见过。一个够到未落地概念的块，会当场失去读者。
- 单位是概念，不是词：通篇没有术语，一个块照样可能倚靠读者并不具备的思路。概念有名字（术语）时，落地意味着把思路和名字一起递到。
- 落地只有两条路：前置（开场前已定，读者自带），或块内引入（某块建立它，此后全文可用）。
- 维护一份已落地清单。当「读者接下来需要听什么」的下一步需要一个未落地概念，这个缺口本身就是答案：先落地它（现在或更早），否则这一步走不动。
- 杠杆在于什么设为前置、什么留在文内落地：前置要太多，把读者挡在门外；文内落地太多，把开头淹死在定义里。确立前置时和用户一起敲定。

## 形式论证：每一块明着谈

每一块用什么形式渲染，都要和用户明着权衡，不沉默决定：

- **散文 vs 列表。** 散文承载论证；列表承载真正并行的条目。不是真并行，用散文；真并行，列表扫得快。
- **行内 vs 提示框（callout）。** 小贴士、警告、旁白只有真会岔开主线时才进提示框；否则留在行内。
- **表格。** 同一形状、同一组字段重复出现 3 次以上才用表；否则用带粗体引导词的散文。
- **直引 vs 意译。** 原措辞本身就是重点才直引；只关心意思就意译。
- **代码块 vs 行内代码。** 多行、可运行、需要展示的用块；单个 token 或标识符用行内。

## 语气（voice）

文章要读起来像一个真实的人或品牌在说话，而不是通用 AI 模板腔。

- 有语气样例时（已发表文章、newsletter、社交帖子、文档、风格指南），从中提取并遵守：
  - 句长与节奏：长句铺陈还是短句连击；
  - 口吻：正式、谈话式，还是犀利；
  - 偏好句式与修辞：括号、列表、短句片段、设问；
  - 对幽默、鲜明观点、逆向思维框架的接受度；
  - 排版习惯：标题、项目符号、代码块、引用的使用密度。
- 没有样例时，默认「实干家」口吻：具体、实用、不夸张其词；短句直给，先例后论。
- 禁用模式，出现即删即重写：
  - 通用开头（「在当今飞速发展的格局中」式套话）；
  - 填充式过渡词（「此外」「而且」）；
  - 夸张词（「游戏规则改变者」「尖端」「革命性」）；
  - 没有证据的模糊断言；
  - 捏造的经历、数字或资质背书。

## 对话式追问：反转拷问五连

这是反向的追问：不问「你注意到了什么」，而问「这篇文章到底在论证什么，读者按什么顺序需要听到它」。顶回去，不许弱过渡滑过去；一段没挣到位置，砍。五个动作反复用：

1. 「这段为读者做了什么，是前一段没做的？」
2. 「砍了它，什么会坏？」
3. 「这是散文，还是该是列表？凭什么？」
4. 「这句在干两件事：拆开，或选一件。」
5. 「开头承诺的是 X，现在已经漂到 Y。要么重新穿线，要么改开头。」

## 堆是采石场，不是剧本

- 采一块碎片，改造成贴合周围段落的形状，放进去。碎片可以拆进多段、与别的碎片合并、或整体意译。
- 堆的职责是被开采；文章的职责是读起来像同一个声音。
- 缺料点名：堆里缺文章需要的东西时，把缺口说破——「这里需要一个例子，堆里没有。现在给一个，或者砍掉这段。」不许沉默补位。

## 写入节奏

- 每块谈定立刻追加进文章文件，不攒批。
- 每次写入前重读文章文件的当前内容：用户可能在两轮之间动过它，绝不盲目覆盖。
- 用户要重写某段：只就地改那一段，其余不碰。

## 借口 vs 现实

| 借口 | 现实 |
|---|---|
| 「形式选择是排版细节，不用谈」 | 形式即论证：散文和列表对读者是两种不同的承诺。不明着谈，就是暗地里替文章做决定。 |
| 「开头反正后面会改」 | 开头定义全文必须做什么；漂移的出路是重穿线或改开头，不是「随便起个头」。 |
| 「堆里没有的，我先编一个垫上」 | 缺料要点名：让用户现在给，或砍段。沉默编造毁掉全文可信度。 |
| 「这段先留着，后面看情况」 | 答不出「砍了它什么会坏」的段，就是没挣到位置。 |
| 「语气是玄学，凭感觉就行」 | 语气全是可核对项：句长、口吻、句式、禁用词，样例里样样提得出来。 |
| 「这个概念读者应该懂」 | 「应该懂」是赌博：没落地就倚靠，赌输就当场失去读者。 |

## 红线自查

- [ ] 原料文件一个字没改，文章是独立文件？
- [ ] 开头是用户从 2–3 个候选里选的或混搭的，不是我替定的？
- [ ] 每一块的形式都明着给过判断依据？
- [ ] 反转拷问五连对可疑段落跑过一遍？
- [ ] 缺料点了名，而不是编造补位？
- [ ] 每块谈定立刻写入，没攒批？
- [ ] 全文无通用开头、填充词、夸张词、无据断言？
- [ ] 没越界：没挖新碎片、没做选题、没做平台排版？

## 越界（out of scope）

- 挖堆里没有的新碎片——缺料按「缺料点名」处理。
- 编辑原料堆文件。
- 发布、面向特定平台的排版、用户没要求的元数据。
