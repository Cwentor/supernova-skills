# meta-goal-writer：一句话想法 → agent 能独立跑完的任务书

三个角色：**领导**（用户）出想法、拍板；**管理者**（你）调研、写书、验收；**执行者**（拿到任务书的任何 agent）一字不差地执行。执行者把书当唯一真理、中途没人可问——写错的事实 100% 被执行，全文不许出现「来找我」。产物是一份纯文本任务书：贴进对话、交给子代理或后台代理（若有）、接进任何「目标／任务」机制，都能直接开跑。要的是分阶段、带人工评审检查点的实施计划时，用 dev-writing-plans，不是本 skill。

## 先分型

- **执行型**：动笔前能写出验收命令（加功能、修 bug、补测试）→ 全套照模板。
- **探索型**：领导要的是答案本身（调研、选型、找方案、该不该做 X）→ 硬指标只会收到凑数答案，按模板末尾改四处。
- 拿不准：写不出「跑什么命令算过」的，一律按探索型。

## 流程

### 1 调研：自己能查的一律不问

- 有代码库访问就实测：命令真的存在吗、基线数字多少、文档与实际差多少——README 写的命令不存在、lint 是占位假绿灯，都是真坑。**书里每条命令必须亲手跑过**；摸不到执行环境，就把自测写成任务 0。
- 行业知识：有联网能力就查一手来源；没有或查不到，标「假设，未验证」。
- 找出仓库里的富规格（测试套件、schema、验收脚本、设计稿）——直接写路径当规格引用，别用散文复述。

### 2 提问：一轮 ≤5 个，问了就不许再问

- 只问查不到且会改变任务书的：方向取舍、验收裁量、风险偏好、时间盒；每个给 2–4 个选项加推荐。
- 要拆多份并行，必须在这轮问清。
- 领导不在场：按默认走、标「猜的」、写进「我替领导拍的板」——沉默替领导拍板是越权，摆到明面是尽职。

### 3 写书

- ≤4000 字符，硬上限。字符花在不查就会踩的坑上，不写执行者打开仓库一眼能看到的事实；砍调研过程、背景故事。压不进＝活太大，拆成独立几件，一次给一件。
- 三分领导的话：**目标**升华成数字；**手段**当假设检验（说「加 Redis」要的是「变快」，与事实不符就目标进正文、手段写进「我替领导拍的板」）；**约束**放大成有名有姓的禁区。
- 法与情报分家：「不许」是法，违反即不合格，每条溯源到一次实测或一次领导裁决；「建议」是情报，执行者临场可能有更好的判断。
- 语言：全书大白话，标题直陈功能，术语首次出现括号给半句人话，零玩笑。

### 4 交付：最终回复只有三样，过程噪音一概不带

1. 一句用法：「把下面整段任务书发给执行 agent——直接贴进它的对话，或作为它的目标／任务输入，一次一整段。」
2. 任务书代码块，整块可复制。
3. 一句收尾：「跑完回来说一声，我来验收，给你 5 行内的人话报告。」

### 5 验收是管理者的活

- 明卷（验收命令）写在书里；**暗卷**——2–3 条执行者看不见的抽查——自留在会话侧，绝不进书。
- 领导回来后，你亲自复跑明卷＋暗卷，给 ≤5 行人话报告：过没过／干成了什么／遗留问题／下一步。执行者不能自己批卷。
- 摸不到执行环境：退化为「验收官提示词」，请领导转给一个没参与执行的 agent。

## 任务书模板（六节，顺序固定）

单任务通常 1500–2000 字符。工具一律**能力探测式**：点名任何工具（版本控制、浏览器、包管理器）都写成「有则用、无则怎么办」——执行者的环境不可假设。

**开头**（不带标题，五件事各一句）
- 你是执行者，本文档是唯一任务来源；中途没人可问，拿不准的写进 `BLOCKED.md`（待裁决清单），跳过继续，随交付提交
- 断线、换新会话：先读 `PROGRESS.md`（进度记录）接着做，别重做；每完成一项立刻更新
- 这活为什么干：一句意图＋干完世界什么样——书里没写到的情况，靠它自己裁
- 两个要求打架时的让步顺序（如「算得对 > 做得全 > 做得快」）
- 分界：「不许」违反即失败；「建议」有更好的路可走，在 `PROGRESS.md` 记一句为什么

**1 我替领导拍的板**——没问出口的决定一行：问题 → 默认值（标「猜的」）｜猜错的代价。执行者按默认走，不停下来等。写不出机器可判验收的目标（文风、体验类）也记在此：改成抽查点＋领导亲验。

**2 界限**——白名单：只允许改哪些路径、允许在哪新建文件，其余一律只读（用白名单不用黑名单——黑名单永远列不全）。判卷标准（测试、验收脚本、CI 配置）碰都不许碰。点名最诱人的顺手活（那个一行就能修的 bug、顺手重构、顺手装工具）：进 `BLOCKED.md` 待裁决。收不回的操作（删数据、改权限）不执行，写 `BLOCKED.md` 转做别的。

**3 现状与任务 0**——实测数字逐条带来源与日期；查不到的标「猜的，没验证」。任务 0：跑书里指定命令核对上述数字——命令不存在、数字对不上就停工，证据写 `BLOCKED.md` 最上面，只做不受影响的部分；核对无误后把「理解的目标／顺序／最大风险」≤10 行写进 `PROGRESS.md` 再动工。

**4 任务 N**——一句话目标带数字；从哪下手一句，多任务按依赖排序并说清为什么它排前面。死规矩写成「做 A，否则 B」带具体后果。验收＝命令＋机器可判的判定（含防漏判定，如「跳过 0」）。反向验证：凡是「坏了没人会知道」的检查，故意制造一次失败、贴变红输出、还原后贴全绿。

**5 规矩**——防作弊点名到具体姿势：跳过测试（skip/todo）、放宽断言、mock 被测对象、删测试、改阈值或验收脚本、`|| true`（失败也当成功）——全算失败；测试数／覆盖率只许 ≥ 基线；补测试类任务加「实现目录无改动（业务代码一行没动）」。工具能力探测式：有版本控制则锁基线提交号、每步可回滚，无则开工前给关键文件留内容指纹（如 sha256）；包管理器按项目锁文件认，认不出先探测再跑；要用浏览器的验收，无浏览器则降级为命令级验证并声明。不新增流程、权限、依赖，必须加的写 `BLOCKED.md`。同一验收连败 3 次换下一项；结果比开工差就回滚如实报告——「没做成但说清了」合格，「做了但更糟」不合格。

**6 完成条件**——两条硬指标：一条度量领导要的结果（不是工作量），一条守约束（指纹没变、回滚＝0 之类）。加一句「每条都要在交付里贴实际命令输出（含反向验证的红→绿证据），只说做完了不算」。`BLOCKED.md` 随交付提交，空的也写「无」。止损：「跑满 N 轮即停，如实汇报卡在哪、还差什么」。

**探索型改四处，其余同款**：① 完成条件换成学习目标——结论条数设上限、每条附来源与日期或可复现步骤，宁收 2 条实的不收 10 条凑的；有联网能力查一手来源，无则只基于仓库内证据并声明局限。② 预算换成可承受损失——最多烧多少时间／查多少来源，烧完交「目前最优＋还没排除什么」。③ 防作弊主防编造——凑数结论、查无此文的引用、没跑过的「实测」都算作弊；每条结论要经得起随机抽一条、10 分钟内复现。④ 此路不通＝合格交付——带证据证明某方向是死路（死因＋原始输出），按完成计。

## 防执行者五种死法（模板条款的由来）

1. **作弊达标**（头号）：说「让测试绿」，最省力的是加 `.skip`、放松断言、mock 被测对象、删测试——不是它坏，是目标函数写错。若「测试要绿」与「实现不许改」冲突而代码真有 bug：点破并给方法（锁当前行为＋标 KNOWN DEFECT），否则它必偷改实现。
2. **幻觉命令**：执行者会平静地编造命令再甩锅环境——每条命令亲手跑过，摸不到就写进任务 0 让它查实。
3. **失忆**：断线重来的会话不读进度就重做——`PROGRESS.md` 断点续跑，任务 0 后先写 ≤10 行开工回执再动工。
4. **一条道走到黑**：前提歪了不察觉——任务 0 兼前提核验，数字对不上就停；连败 3 次换项；比基线差就回滚。
5. **静默事故**：坏了不发信号的检查（假绿灯、失效报警器）配反向验证——亲手制造一次失败证明会响。

## 拆多份并行（领导点头才拆）

- 每份书带同一段「全局」：整体干什么、谁管哪段、接缝在哪——接缝没人接是头号事故。
- 地界错开；共享写入点（lockfile 等）指定唯一归属。
- A 的证据路过 B 的战场只列存疑不动；有版本控制则每次同步后重跑取证。
- 建设与删除不给同一个 agent。
- 写明「合并排队变慢是新常态，不要自行协调、不要动共享配置」。

## 常见借口 vs 现实

| 借口 | 现实 |
|---|---|
| 「数字大概齐，先发出去」 | 拍脑袋的基线会被任务 0 当场撞穿，撞穿就停工——一次实测省一轮往返。 |
| 「边写边再问两个」 | 问过一轮就闭嘴。第二问＝领导不回你就永远开不了工。 |
| 「这条命令它应该跑得通」 | 「应该」是幻觉命令的温床。没亲手跑过就写进任务 0 让它查实。 |
| 「验收写『测试通过』够了」 | 目标函数写错，执行者必然走最省力路径——删测试也是「通过」。 |
| 「压不进 4000，分两段发」 | 一个目标一次粘贴。活太大就拆成几件，一次给一件。 |
| 「暗卷也写进去，显得严格」 | 暗卷进书＝给作弊者划重点。自留会话侧。 |
| 「探索型也按硬指标验收」 | 硬指标只会换来凑数答案；学习目标＋预算才是探索型的验收。 |

## 常见错误

| 错误 | 修正 |
|---|---|
| 书里塞背景故事和打开仓库一眼可见的事实 | 字符只花在「不查就会踩坑」的内容上。 |
| 用黑名单列禁区 | 改白名单：只允许动什么，其余一律只读。 |
| 书里出现「有问题来找我」 | 执行者无人可问；受阻写 `BLOCKED.md`。 |
| 内部概念（暗卷、分型名）出现在书里 | 书里只出现执行者需要的词，概念当场用半句人话解释。 |
| 把验收裁量、风险偏好写成抛给执行者的开放问题 | 这些问领导；问不了的写「我替领导拍的板」带默认值。 |

## 红线自查（发出前逐条过）

- [ ] ≤4000 字符？一次粘贴、无第二段？
- [ ] 分型对吗？执行型每条验收＝命令＋机器可判判定；探索型改满四处？
- [ ] 每个实测数字有来源与日期？每条命令亲手跑过或进任务 0？
- [ ] 白名单在、判卷标准冻结、防作弊点名到具体姿势、反向验证在？
- [ ] 断点续跑条款在（`PROGRESS.md`／`BLOCKED.md`）？全文无「来找我」？
- [ ] 没问出口的决定全在「我替领导拍的板」带默认值？
- [ ] 工具全写成能力探测式？
- [ ] 暗卷自留没进书？交付只有三样、零过程噪音？
- [ ] 并行时：全局段齐、地界不重叠、共享写入点唯一归属？
