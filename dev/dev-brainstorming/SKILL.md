# dev-brainstorming：把想法谈成设计

创作前门禁：动第一行实现代码之前，先把「要做什么、给谁做、做成什么样算成功」谈清楚。产出是用户认可的设计，不是代码。

## 建立共同理解

1. **挖意图**：从请求与现有上下文里找出预期结果、给谁用、成功标准。缺什么就问什么——在提方案之前，先问一个聚焦「目的/用途」的问题。知道 app 是什么类型 ≠ 知道用户为什么想要它。
2. **写回理解**：用一段简短的话复述你理解的预期结果、约束与成功标准，**把用户说过的与你的假设分开标注**，请用户确认或纠正。
3. **意图带进设计**：选定的方案要保住这份共同理解；后续每个功能点与技术选择都对照它检验。

请求已自带目的与约束时，直接复述确认，不要把问过的问题再问一遍。

## 先分类，再动工

提第一个问题之前，先判断这个请求需要哪条路径，**并把判断说出来**（让用户有机会纠正）：

| 路径 | 什么样 | 产出 |
|---|---|---|
| **Spike（探针）** | 一个可行性问题（「能不能…」「快糙猛就行」） | 一个答案 + 建议；做出的任何东西标注一次性 |
| **Bounded（有界）** | 对仓库**已存在**流程的收口改动：开关、小端点、单文件修复 | 聊天里几句话的短设计，确认后直接实现 |
| **Architectural（架构级）** | 新项目、新子系统、改组件间结构或他人依赖的接口 | 完整过程 → 规格文档（dev-spec）→ 实施计划 |

判不准时**走重的那条**。棘轮单向：中途发现藏着的复杂度 → 停下、说明、升路径；没有任何中途降级。

## 硬门禁（HARD-GATE）

实现动作（写产品代码、脚手架、装产品依赖、建外部项目）开始前，必须完成当前路径的前置：

- Spike：用户点头同意「问题 + 探法」。
- Bounded：用户对聊天里的短设计明确说「可以」。
- Architectural：规格写完并经用户审阅认可，才许起草实施计划（dev-writing-plans）。

**一次确认只覆盖当前展示的那个阶段。** 认可一个想法 ≠ 认可还不存在的文档。前一个阶段没完成就从最早未完成处恢复，不许把一次批准兑换成跳步。前置未完成期间，只读探索项目可以做。

## 架构级路径

1. 摸清现状：文件、文档、近期提交。
2. 范围先行：请求若是多个独立子系统的组合（「做个带聊天、存储、计费、分析的平台」），先帮用户拆成子项目、定先后顺序，再谈第一个；每个子项目各自走规格→计划→实现。
3. 一次只问一个问题（优先选择题），弄清目的 / 约束 / 成功标准。
4. 提出 2-3 个方案：带取舍与你的推荐及理由；**YAGNI 下狠手**，把每个方案里不必要的功能砍掉。
5. 分节呈现设计，每节按复杂度定篇幅，逐节确认；覆盖：架构、组件、数据流、错误处理、测试。
6. 规格固化与审阅交给 dev-spec；规格认可后接 dev-writing-plans。

**设计单元纪律**：把系统拆成单一职责、接口清晰、可独立理解与测试的单元；判据——不看内部实现能明白它做什么、改内部不破坏调用方。文件膨胀通常是「干太多事」的信号。

**在既有代码库里**：先探索再提案，遵循既有模式；只把与本次目标相关的改进纳入设计，不顺手提无关重构。

## 常见借口 vs 现实

| 借口 | 现实 |
|---|---|
| 「太简单，不用设计」 | 每条路径都要对应的确认物：有界改动要聊天短设计，架构级要规格；简单只是缩小确认物，不是取消确认 |
| 「我把它叫有界，跳过规格」 | 为了跳工作而挑标签本身就是那个疑点——走重的那条 |
| 「有界且方案显然，我边写他们边看」 | 门禁是「确认」不是「篇幅」；展示完停下等明确的 yes |
| 「我懂这类 app，所以是有界」 | 有界量的是仓库不是你的熟悉度；没有既有流程可改的就是架构级 |
| 「探针跑通了，代码就留着吧」 | Spike 的产出是答案；留代码是新请求，重新分类 |
| 「长复杂了，但快完事了，不用重分类」 | 中途暴露的复杂度必须升路径；停下、说明 |
| 「探针批了，后续改动也算批了」 | 每个任务各自分类、各自过门禁 |

## 红线自查

- [ ] 动手前完成路径分类并说出来了？
- [ ] 实现代码一行没写，直到对应确认物拿到明确的 yes？
- [ ] 理解已复述，用户说的与我的假设分开标注？
- [ ] 每条消息最多一个问题？
- [ ] 方案砍过 YAGNI，没有为假想需求设计？
- [ ] 中途变复杂时升级了路径而不是硬撑？

**相关技能**：架构级产物 → dev-spec → dev-writing-plans → dev-executing-plans；有界实现 → dev-tdd；拿不准某个状态模型成不成立 → dev-prototype（探针的代码形态版）。
