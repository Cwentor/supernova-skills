# dev-domain-modeling

主动**建立并打磨项目的领域模型**：挑战含糊术语、拆解一词多义、发明边界场景逼出精确度，并在术语与决策**定型的当下**写进文档。只是读取 CONTEXT.md 取词不算本技能——本技能用于**改变**模型，不是消费模型。

## 文件结构（惰性创建）

- 单一上下文（多数仓库）：根目录一个 `CONTEXT.md`，决策记录在 `docs/adr/`。
- 多上下文：根目录 `CONTEXT-MAP.md` 指向各上下文（如 `src/ordering/CONTEXT.md`），各自带 `docs/adr/`；跨上下文的决策记在根 `docs/adr/`。当前话题归属不清时先问。
- 按需创建：第一个术语敲定时才建 `CONTEXT.md`；第一个 ADR 出现时才建 `docs/adr/`。

## 会话中的动作

- **对着术语表挑战**：用户用词与 CONTEXT.md 冲突时当场指出：「术语表把『取消』定义为 X，你现在说的像 Y，是哪个？」
- **拆解一词多义**：听到含糊或超载的词就提出规范词：「你说的『账户』是 Customer 还是 User？这是两个东西。」
- **用具体场景拷问**：讨论领域关系时，发明探边界的场景逼出精确：快乐路径、刁钻边界、应当被禁止的操作。
- **与代码交叉验证**：用户陈述某机制时核对代码是否同意；矛盾就摆出来：「代码只能整单取消，你刚说可以部分取消——哪个对？」
- **当场更新 CONTEXT.md**：术语一定型就写进去，绝不攒批；攒批的结果是细节已流失、转述已走样。

CONTEXT.md 只是术语表：**彻底不含实现细节**——不当 spec、不当草稿本、不当实现决策的仓库。

## CONTEXT.md 条目格式

```md
# {上下文名称}

{一两句话：这是什么上下文、为何存在}

## Language

**Order**:
{一两句话定义：它是什么，而非它做什么}
_Avoid_: Purchase, transaction

**Invoice**:
交付后向客户发出的付款请求
_Avoid_: Bill, payment request
```

规则：**有主见**——同一概念多个词时选定最佳者，其余列进 _Avoid_；**定义紧凑**——至多两句；**只收本上下文特有的概念**——timeout、错误类型这类通用编程概念不收，哪怕项目里用得很多；自然成簇的词用小节分组。

## ADR：三条件门

**同时满足**三条才提出记录 ADR，缺任何一条就跳过：

1. **难以逆转**：反悔的成本显著；
2. **离开上下文会显得奇怪**：未来读者会问「当初为什么这么做？」；
3. **真实权衡的产物**：存在真正的备选，且因具体理由选了这一个。

容易逆转就直接逆转；不奇怪就没人会问；没有真备选就只是「做了显然的事」。合格题材：架构形状（monorepo、事件溯源写模型）；上下文间的集成模式（领域事件而非同步调用）；带锁定的技术选型（数据库、消息总线、部署目标——不是每个小库）；边界与归属决策（明说不与明说同样有价值）；对显然路线的刻意偏离（防止下一个人「修好」故意为之的东西）；代码里看不见的约束（合规禁用某云、接口延迟上限）；因非显然理由被否掉的备选（否则六个月后有人会再提一遍）。

ADR 存于 `docs/adr/`，顺序编号 `0001-slug.md`（取现有最大号 +1）。正文只需：

```md
# {决策短标题}

{1–3 句：背景是什么、决定了什么、为什么}
```

价值在于记下「做过这个决定」和「为什么」，不在填表。Status、Considered Options、Consequences 只在真有增量时才加。

## 边拷问边落档

当一场设计讨论反复绕圈、难有进展时，把拷问产出的结论**当场**沉淀下来：每敲定一个术语就写术语条目；每否决一个有分量的方案就写一条 ADR。落档让讨论产生不可逆的进展；绕圈的根源往往正是同一个词被两边当作两个东西在用。

## 常见借口 vs 现实

| 借口 | 现实 |
|---|---|
| 「等收尾时一次性把术语表补全」 | 定型当下不写，转述必然走样；批量补记 = 补一批二手信息。 |
| 「这个决定也记个 ADR 吧」 | 三条件缺一就跳过；ADR 泛滥的目录里没人找得到真决策。 |
| 「CONTEXT.md 顺便写上实现要点」 | 它是术语表且只是术语表；混入实现细节后没人再信任它。 |
| 「术语差不多就行，大家都懂」 | 一词二义正是 bug 和绕圈讨论的来源；「都懂」的内涵往往各不相同。 |

## 红线自查

- 听到含糊或超载的词，没提出规范词 → 提出
- 术语已定型，没写进 CONTEXT.md → 当场写
- 想记的 ADR 三条件缺一 → 跳过
- CONTEXT.md 里出现实现细节或 spec 内容 → 删出
- 领域描述与代码矛盾，没向用户指出 → 指出

## 常见错误

- 收录通用编程概念（timeout、工具模式），稀释术语表。
- 定义写成「它做什么」——应定义「它是什么」。
- ADR 填满全部模板节，把记录变成文书工作。
- 多上下文仓库里不查 CONTEXT-MAP.md，把条目写错位置。
