# dev-tickets：拆出曳光弹票据

把规格、计划或一段讨论拆成一组**票据**并发布到项目 tracker：每张票是一条打穿全部层次的曳光弹（tracer bullet）竖切片，声明自己的阻塞边，任何 agent 拿到即可独立执行。

**衔接：** 输入通常来自 dev-spec（规格）或 dev-writing-plans（计划），也可以是当前讨论；产物（票据组）交给 **dev-executing-plans** 按 blockers-first 顺序执行。拆完即交棒，本 skill 不执行。

## 票据三原则

1. **自包含**：任何 agent 只读这张票（加上代码库本身）就能开工、能验收。不引用会话记忆；会话里有什么票需要的东西，先写进票里。
2. **竖切完整**：每张票切一条窄但**完整**的路径（schema、API、UI、测试全打通），不是按层横切；完成的切片独立可演示、可验证。
3. **声明阻塞边**：每张票明确列出哪些票必须先完成（**Blocked by**）；无阻塞则明写 None（可立即开工）。

尺寸标尺：一张票要装得进一个全新会话的上下文窗口。

## 流程

### 1. 收集上下文

- 用户给了引用（规格路径、issue 编号或 URL）→ 取全文连同评论读完。
- 没探索过代码库就补一次：票面用项目的领域词汇，尊重相关区域的 ADR。
- 顺手找**预重构**（prefactoring）机会：「先让改动变容易，再做容易的改动」；预重构单独成票，排最前。

### 2. 工作大到装不下？先拆决策票据

工作大到单个会话装不下、且前路有雾（连「要建什么」都说不清）时，不要急着切实现票。先拆**决策票据**：每张是一个已经锋利的问题，解决它 = 产出一个决策（选型、schema 走向、边界画在哪）。逐个解决，雾随之向后退；每个新决策让原本切不出来的实现票变得可切，这时再回来切实现票据。

雾的判据：**问题现在就能精确陈述**（哪怕仍被别的决策阻塞）→ 成票；问题还提不出来 → 写进「待厘清」清单，不要把雾预切成票的样子——雾比票粗，等前沿推进到它自然显形，一块雾届时可能散成几张票，也可能散成没有。

### 3. 起草切片

按三原则切曳光弹票。

**宽改动是竖切的唯一例外**：一次机械变更（重命名一列、改共享符号类型）波及全库时，任何竖切片都红。改排 expand–contract：先 **expand**——新形态与旧并存，什么也不破坏；再按波及面分批迁移调用点（每批一张票，阻塞于 expand，旧形态仍在所以批批保绿）；最后 **contract**——删旧形态（阻塞于全部迁移批）。连批次都保不住绿时：各批共享集成分支，全部阻塞一张最终「集成并验证」票，绿色只在终点承诺。

### 4. 请用户过一遍

以编号清单展示，每张票给三行：**标题** / **Blocked by** / **交付什么端到端行为**。问三件事：

- 粒度对吗（太粗 / 太细）？
- 阻塞边真实吗——每张票只依赖真正卡住它的票？
- 有该合、该拆的吗？

改到用户点头为止。

### 5. 发布（tracker 能力探测）

- **有真实 issue tracker 工具**（能通过 CLI、API 或专用工具建 issue）→ 按依赖序（blockers 在前）逐张发布原生 issue，让阻塞边能引用真实编号；用平台**原生**的 blocking / 子任务关系，没有这种关系才退回票面写 Blocked by。打 agent 就绪标签（约定名 `ready-for-agent`；项目词表有映射则用映射名）。
- **没有** → 本地 tracker：项目约定目录（如 `.scratch/<feature-slug>/issues/`，无约定则与用户定一个）下**一票一个文件** `<NN>-<slug>.md`，从 `01` 起按依赖序编号，票面「Blocked by」写所依赖票的编号/标题。一票一文件，永不合并成单文件。

**执行口令是 frontier**：执行方永远拿「阻塞已全部完成」的票；纯线性链就是从上往下。不要关闭或改动父 issue / 父规格。

## 票面模板

```markdown
# <NN>: <标题>

**What to build:** 这张票交付的端到端行为（用户视角），不是逐层实现清单。
**Blocked by:** 所依赖票的编号/标题，或 "None (can start immediately)"。
**Status:** ready-for-agent
**Parent:** 来源规格 / issue 的引用（有则写）。

- [ ] 验收标准 1（独立可验证）
- [ ] 验收标准 2
```

与规格同款约束：票面不写文件路径、行号、代码段——它们最快过时。例外：原型产出的、比散文更精确编码决策的片段（状态机、reducer、schema、类型形状），内联、注明来自原型、裁剪到决策本身。

## 常见错误

- **横切片**：先做全部 schema、再做全部 API……每张票都无法独立验收，集成爆炸留到最后。
- 漏写阻塞边，或写不真实的边（把「顺手相关」当「必须先有」），frontier 排错队。
- 票面引用会话记忆（「如前所述」）——换一个 agent 执行当场卡死。
- 一票多义或巨票：装不进一个会话还硬不拆。
- 决策票据没清完就切实现票，切出来全是雾。
- 预重构和实现混进同一张票，验收标准互相纠缠。

## 红线自查（发布前过一遍）

- [ ] 每张票只读票面 + 代码库即可独立执行并验收。
- [ ] 每张票完成即有可演示 / 可验证的端到端行为。
- [ ] 每张票的 Blocked by 写明（无则明写 None）。
- [ ] 发布顺序 = 依赖序，blockers 在前。
- [ ] 用户已确认粒度与阻塞边。
- [ ] 票面无路径 / 行号 / 大段代码（原型决策片段除外）。
